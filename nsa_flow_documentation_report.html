1. Resolving the Namespace Traceback

The traceback help(nsa_flow.nsa_flow.NSAFlowLinear) caused an AttributeError because nsa_flow.nsa_flow is the core solver function imported into the package namespace, not a submodule:

# Incorrect:
>>> help(nsa_flow.nsa_flow.NSAFlowLinear)
AttributeError: 'function' object has no attribute 'NSAFlowLinear'

# Correct (both fully supported & documented):
>>> help(nsa_flow.NSAFlowLinear)         # Top-level re-export

nsa_flow/__init__.py now explicitly documents this layout in its package docstring.

2. Deep Dive: What NSAFlowLinear Does

nsa_flow.layers.NSAFlowLinear is a drop-in replacement for PyTorch's nn.Linear (matching weight shape [out_features, in_features] and state_dict) whose $k = \text{out\_features}$ filters are driven toward orthogonality and disjoint feature clustering:

Mode Configuration Mathematical Mechanism Execution Cost
Forward Parameterization w > 0, nonneg=None Stiefel blend: $W_{\text{eff}} = (1-w)W + w P(W)$ via Newton-Schulz or polar factor Fast; cached in eval()
Non-Negative Defect Blend w > 0, nonneg="hard" Continuous blend $W_{\text{eff}} = (1-w)\max(0, W) + w P_{\text{nonneg}}(W)$ with $P$ run for n_steps (default 8) Branchless & compilable; strictly monotonic across full $[0, 1]$ range
Penalty Regularizer w = 0 Forward pass is plain linear; add $\lambda \cdot \text{layer.defect()}$ to loss $\mathcal{O}(p k^2)$ Gram algebra, 0 factorizations
Exact Certified Solver operator="solver" Exact anchored nsa_flow(mode="anchored", fidelity="anchor") prox in forward pass (identical to project_()) + STE for autograd ~0.5ms; 100% mathematical parity with nsa_flow, smooth support shrinkage across $[0,1]$
